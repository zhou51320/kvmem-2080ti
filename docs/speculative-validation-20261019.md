# Shared speculative contract and native DFlash2 validation

> Device identifiers and private paths have been anonymized; reported measurements are unchanged.

All successful GPU checks for this integration used the explicitly selected RTX 5060 Ti, UUID `GPU-B`. The host runs Windows, CUDA 13.2 and MSVC 19.44. Compilation used eight jobs. No new throughput comparison, 256K task or RC3 run was performed.

The trained llama.cpp check answered READY, red and red. Its three requests recorded four verification rounds, 20 candidate tokens and two accepted candidates. The NInfer check recorded one round, five candidate tokens and one accepted candidate. These deliberately short workloads exercise real acceptance paths; their acceptance ratios and elapsed times are not performance conclusions.

The untrained fixture is generated by `tests/make-dflash2-fixture.py` from target tokenizer metadata and deterministic synthetic draft weights. It tests the native DFlash2 rejection and state paths without another large model download. Zero accepted drafts in that fixture is expected and does not measure trained-head quality. The session test recovered historical prefixes of 1263, 1779 and 1806 tokens and completed the two requests after cancellation.

Reproduce the state check with the pinned backend's `gguf-py`, NumPy and a target containing the expected tokenizer and feature geometry:

```powershell
python tests/make-dflash2-fixture.py --target 'D:/models/Qwen3.5-0.8B-Q8_0.gguf' --output 'D:/tests/dflash2-fixture.gguf'
python tests/session-restore-regression.py --exe 'D:/build/llama-kvmem-server.exe' --model 'D:/models/Qwen3.5-0.8B-Q8_0.gguf' --dflash2-draft 'D:/tests/dflash2-fixture.gguf' --gpu 'GPU-B' --mtp-state snapshots --turns 2 --cancel-rounds 1 --out 'D:/tests/dflash2-session'
```

## Model and build provenance

The trained target is `Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp.gguf`; the existing companion is `Qwen3.8-27B-DFlash2-Q4_K_M.gguf`, SHA-256 `1a25c56858e1ebe93f2718ac1d49d1151f9323325c1bbfd6209370f4db131ebd`, previously downloaded through hf-mirror. The CPU projector is `mmproj-Q8_0.gguf`. NInfer uses the existing `Qwen3.8-27B-IQ3_S-vision-mtp-dflash2-Q4_K_M.ninfer` artifact. No model download was needed for these checks.

llama.cpp builds from the pinned `620d2225cc436ab0b001e3200e590e3b286ef9ab` plus the integration patch. NInfer remains pinned to `08fd7019925f43b4b42539400afd461b70f7144a`. Its changes in this task are limited to four serving/build files. All 36 serving/application CPU translation units were rebuilt, linking the existing native libraries only after checking that the native source files match the previously validated integration. This is a serving rebuild, not a fresh rebuild or requalification of NInfer CUDA kernels.

## Failures corrected during validation and remaining scope

An early incremental Windows build retained stale objects because Ninja did not recognize the localized MSVC include prefix. Correcting dependency tracking and rebuilding the affected host objects resolved the teardown/request crashes. An early synthetic fixture also used invalid FP16 norm/conv tensor storage; generating those tensors in the expected FP32 storage resolved its CUDA assertion. The final CLI rebuild initially exposed an internal header include-path error, which was corrected. These invalid build/fixture attempts are excluded from the passing results above.

The common launcher offers llama.cpp widths one through five and DFlash2 on one lane/one GPU. Adaptive DFlash2, multi-GPU DFlash2, trained-head quality, additional KV formats, and long-context llama.cpp performance are outside this validation. Historical checkpoints serialize the draft's native cache, adding storage/transfer work at those boundaries; that cost has not been benchmarked. Existing NInfer 256K measurements are not transferred to llama.cpp by this integration.
