# NInfer CPU 视觉按需加载与空闲回收验收（2026-10-20）

本文记录 2026-10-20 原始实现的验证。2026-10-23 合入时已移植到版本清单指定的
当前 NInfer pin；本次移植的重新构建和回归结果单独记录在合并 PR 中。

Qwen3.5/3.6/3.8 的 CPU 视觉塔改为首次实际编码时加载，最后一个编码器释放权重后，
默认空闲 **300 秒**自动卸载。文字请求不触发加载；后续需要编码的图片会重新加载。
活跃编码器通过共享读引用保护权重；回收线程独立运行，不依赖新请求或 `/props` 轮询。
设置 `--cpu-vision-idle-seconds 0` 可关闭定时卸载，仍保持按需加载。
Windows 启动器对应参数为 `-CpuVisionIdleSeconds`，默认值相同。

这是源码和本轮新编译 worker 的行为，已有发布包不会自动改变。

- 主仓库基线：`61569ff4bddcad60e8fad838e02f77a6190126d1`。

- CPU：Intel Core Ultra 7 255H；GPU：RTX 5050 Laptop 8 GiB，通过 UUID 选择并由 `/props` 核实。

  视觉塔来自 Qwen3.8-27B IQ3_S 视觉制品；共 409 个对象逐字节复制并校验 SHA。
  未重新量化，文件大小 2,740,508,928 字节。缩减文字层只是为了适配 8 GiB 显卡。

  图片为 64×64 PNG，单图视觉上限 64 merged tokens。

本轮验证资源生命周期、原生数值测试和服务恢复，不构成完整 27B 模型的语义质量、256K、
DFlash2 长任务、多卡或吞吐验收；未使用 RTX 5060 Ti。Gemma 的独立 CPU 实现不在此改动范围内。

## 实际服务与内存

HTTP 回归为了缩短等待，将同一回收机制的超时覆盖为 **2 秒**；每次空闲等待 3 秒，期间不发请求，
也不轮询状态。产品默认 300 秒由原生参数测试和启动器测试确认，本轮没有等待完整五分钟。

最终运行完成了 10 个成功请求及 1 个预期失败请求，服务正常退出。单图、同请求双图、
两个并发图文请求均通过；连续使用不增加加载次数，两次空闲回收后权重字节数均为 0。
卸载后的文字请求继续保持未加载。

| 时点 | 视觉权重 MiB | 加载/卸载次数 | 进程私有内存 MiB | 进程工作集 MiB |
| --- | ---: | ---: | ---: | ---: |
| 启动就绪 | 0 | 0/0 | 3587.6 | 1733.0 |
| 纯文字后 | 0 | 0/0 | 3927.7 | 2067.8 |
| 连续单图与双图后 | 1757.5 | 1/0 | 6068.5 | 4203.3 |
| 第一次空闲回收后 | 0 | 1/1 | 4308.5 | 2446.9 |
| 重载及并发请求后 | 1757.5 | 2/1 | 6368.8 | 4501.2 |
| 第二次空闲回收后 | 0 | 2/2 | 4608.8 | 2744.8 |
| 文件不可读的失败请求后 | 0 | 2/2 | 4578.8 | 2715.1 |
| 文件恢复、图片成功后 | 1757.5 | 3/2 | 6370.4 | 4503.0 |

视觉权重逻辑大小为 **1,842,920,384 字节（约 1.72 GiB）**。两次回收均使进程私有内存减少约
1760 MiB、工作集减少约 1756 MiB。进程仍持有文字模型、KV、预处理及其他运行资源，
因此不能把剩余总内存归为视觉权重。

最终运行中，纯权重读取和解码分别为首次 **4.46 秒**、空闲后重载 **3.58 秒**、故障恢复后
**3.71 秒**；对应首图整请求 7.45 秒、热单图 2.89 秒。它们是本机功能联调观测值，
没有做冷磁盘缓存控制，也不是与旧版的性能比较。实际图片尺寸会影响编码时间。

图片预处理缓存不等于完整 KV 或视觉 embedding 命中；重复发送同一张图片仍可能实际编码，
从而在超时后重新加载。已完成结果和缓存不持有 CPU 视觉权重租约。

## 加载失败处理

测试只临时重命名其自行复制的单文件制品，原始模型未移动。权重已卸载时，图片请求得到
HTTP 503 `service_unavailable`；加载计数和权重字节数不变，`/health` 继续正常。
还原文件后，文字请求和下一次图片请求均成功，后者成为第 3 次成功加载。

新增资源错误会跨过内外两层 prefill 的通用执行失败清理，保留请求归属，交给 Engine
在安全边界中止；失败请求不发布可变端点状态。此处理仅针对新增的按需加载错误。
启动仍做逻辑绑定、形状及支持格式检查；读取时复核制品 ID。模型须保留在原始入口路径。

## 复现入口

```powershell
python tests/ninfer_cpu_vision_lifecycle.py `
  --exe D:/build/apps/ninfer-serve.exe --model D:/models/four-layer-vision.ninfer `
  --gpu GPU-your-5050-uuid --out D:/results/cpu-vision-new-run `
  --idle-seconds 2 --fault-injection
```

输出目录必须是新目录。故障注入只支持可直接复制的单文件测试制品，并需要额外一份文件空间。
脚本输出 `summary.json`、请求响应和服务日志；Windows 额外记录进程工作集及私有内存。
原生测试目标为 `ninfer_cpu_vision_cache_test` 和 `ninfer_cpu_vision_tests`；后者按上表测试名选择运行。
